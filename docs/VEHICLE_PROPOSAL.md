# 提案：SuperMimic for Vehicles：用一个可微世界模型学车辆极限操控

状态：设计稿（2026-11-03），尚未实现。它是 [`RESEARCH_DIRECTIONS.md`](RESEARCH_DIRECTIONS.md) §6.5 的展开版。

一句话：把 SuperMimic 的配方原样搬到车辆上。用一个确定性世界模型学同一辆车在所有工况下共享的动力学，数据来自不可微的高保真车辆仿真器；策略沿世界模型做短视野 BPTT 加 critic，在一个大型参考轨迹库上学会跟踪，并把训练集中到附着极限附近。

---

## 1. 为什么车辆极限操控是好的迁移目标

按 `RESEARCH_DIRECTIONS.md` §6.1 的六个条件逐条对照：

| 条件 | 人形跟踪 | 车辆极限操控 | 判断 |
|---|---|---|---|
| C1 动力学跨任务共享 | 所有动作共享一个身体 | 所有轨迹、赛道、机动共享一辆车 | ✓ 完全同构 |
| C2 奖励可微、可解析 | 经 FK 的跟踪奖励 | 经 Frenet 投影的跟踪奖励（横向误差、航向误差、速度误差） | ✓ 比人形还简单，不需要 FK |
| C3 状态结构化 | 约 70 维 | 约 25–35 维 | ✓ |
| C4 动力学光滑 | 接触切换 | 轮胎饱和；ABS/ESC、换挡等逻辑不连续 | △ **主要风险**，见 §8 |
| C5 便宜的数据源 | GPU 并行刚体仿真 | GPU 并行双轨模型 + Pacejka 轮胎，易达 10⁶ 步/s 量级 | ✓ |
| C6 短视野 + critic 足够 | 0.64 s 覆盖动作瞬态 | 横摆/侧向瞬态 0.1–1 s；纵向（入弯前刹车）需要 2–4 s | △ 需要更长的参考预览，H 需要扫描 |

另外两项加分：

- 高保真车辆仿真器（多体模型、MF 6.x 轮胎、ESC 逻辑）大多**不可微**，正是“从黑盒仿真器日志学可微代理”的用武之地；
- 现有的学习式赛车/漂移控制要么是模型无关 RL，算力很大（GT Sophy，Nature 2022；Fuchs et al., RA-L 2021），要么是 NMPC（Kabzan et al., RA-L 2019 的学习式 MPC；Goh & Gerdes 的漂移控制）。“单卡小时级、一个策略覆盖上万条轨迹和整个摩擦区间”的位置是空着的。

与已有可微驾驶工作的区别：

- Waymax 上的 APG（Nachkov et al., IROS 2025）和 Dream to Drive / Analytic World Models（AAAI 2026）用的是**解析可微的运动学模型**，没有轮胎，也不涉及极限工况；
- Song, Kim & Scaramuzza（CoRL 2025）在四足上用简化可微代理求梯度，再用高保真仿真器做前向。本提案对应的是“**学**出来的代理，加车辆极限工况”。

## 2. 对 §6.5 原稿的修正

| 原稿 | 问题 | 修正 |
|---|---|---|
| “失控（横摆角或侧偏角超限）作为终止” | 漂移本身就是大侧偏角，按绝对值终止会把漂移参考全部判成失败 | 终止相对**参考**定义，与 SuperMimic 的“根部相对参考偏离”一致：\|e_y\| > 阈值、\|e_ψ\| > 阈值、\|β − β_ref\| > 阈值，或驶出路面边界 |
| “ξ 包含执行器延迟” | 延迟不是一个可以在每步动力学里查到的参数：系统状态必须包含尚未生效的指令，否则不满足马尔可夫性 | 把动作缓冲（最近 d 步指令）放进状态 s；ξ 里只放延迟的**步数**，用来选择缓冲的读出位置 |
| “从真实驾驶日志和赛车线生成参考轨迹” | 同一条参考在 μ=1.0 时可行，在 μ=0.5 时不可行。人形的“可行性过滤”在这里和 ξ 耦合 | 参考按 ξ 生成：路径几何不变，速度曲线由 g-g 图（随 μ 缩放）重新规划；或者参考只给路径几何加“目标速度比例”，见 §4 |
| “以未来 K 个参考点为目标” | 原稿默认 K 个时间步，50 Hz 下 K=10 只预览 0.2 s，不够入弯前刹车 | 用**空间或时间不均匀采样**的预览：近处密、远处疏，覆盖约 3 s（例如 0.1, 0.2, …, 1.0, 1.5, 2.0, 3.0 s，共 K≈14） |
| “失控作为学习式终止头” | 终止是状态和参考的确定性函数，学出来反而引入误差 | 默认用**解析**的软终止（对阈值取 sigmoid），并与学习式终止头做消融 |
| 胎温进入状态 | 胎温变化的时间常数是几十秒，远超 H，在想象窗口里几乎是常数 | 胎温放进 ξ 的“慢变量”部分，每回合随机初始化，只在仿真器里演化；世界模型以当前值为条件，不预测它 |

## 3. 系统设计

### 3.1 仿真器（数据源）

- **主力**：GPU 批量的双轨（四轮）车辆模型，包括：
  - 车身 6 DoF：纵向、侧向、横摆，加上侧倾、俯仰、垂向的简化悬架；
  - Pacejka MF（组合滑移）轮胎，加松弛长度；
  - 载荷转移；
  - 转向执行器的一阶滞后和速率限制，驱动/制动扭矩的滞后和饱和；
  - 刻意加入**不可微元素**：ABS 和 ESC 的门限逻辑、离散换挡、路面 μ 的分段跳变（split-μ、μ 阶跃）。

  用 Warp 或 JAX 实现，4096–16384 个并行环境。它虽然理论上可微，但**训练时把它当黑盒**，这样可以和“直接沿仿真器求导”（∇Mimic 式）做对照。
- **参照**：CommonRoad 的多体车辆模型（TUM Althoff 组开源，含 MB 模型和轮胎模型）作为独立实现，用来核对主力仿真器的稳态和瞬态响应（阶跃转向、正弦停顿 sine-with-dwell、双移线 ISO 3888）。
- **后续**：商业高保真工具（CarMaker、VI-grade 等）只用于离线验证和少量数据采集，不进训练循环。

### 3.2 参考轨迹库（对应动作库）

| 来源 | 内容 | 规模（目标） |
|---|---|---|
| 赛道 | 公开赛道中心线和边界（例如 TUMFTM 的 racetrack-database），最小曲率或最短时间赛车线（例如 TUMFTM 的 global_racetrajectory_optimization），按多个 μ 和速度比例重新规划速度曲线 | 约 20 条赛道 × 10 个 μ × 5 个速度比例 → 切成 10–20 s 的片段，数万条 |
| 标准机动 | ISO 3888-1/-2 双移线、麋鹿测试、正弦停顿、阶跃转向、开环 J-turn，覆盖不同速度和 μ | 数千条 |
| 真实驾驶日志 | highD、nuPlan 等的自车轨迹（正常工况，用于覆盖低激励区） | 数千条 |
| 漂移 | 用非线性最优控制（例如 acados 加单轨模型）生成稳态漂移平衡点和漂移过渡段，参考同时给出 β_ref、r_ref | 数千条 |

**可行性**：每条参考连同 ξ 一起，先在仿真器里用一个强基线（NMPC 或 PPO 教师）试跑，跟不住的标为不可行，不进训练库（对应 BONES-SEED 的可行性过滤）。也可以只做 g-g 包络检查（|a| ≤ μ·g·安全系数），作为便宜的近似。

**Held-out 划分**（从第一天就固定）：

- `heldout_track`：整条赛道留出；
- `heldout_maneuver`：整类机动留出（例如训练不含麋鹿测试）；
- `heldout_mu`：μ 区间外推，例如训练 μ∈[0.4, 1.1]，测试 0.3 和 1.2。

### 3.3 状态、动作、ξ

**状态 s**（约 30 维，航向规范化）：

| 组 | 量 |
|---|---|
| 位姿 | x, y, ψ（世界系；网络输入只用航向规范化后的量，见下） |
| 车身速度 | v_x, v_y, r（车身系），侧倾角 φ、俯仰角 θ 及其角速度，垂向位移和速度 |
| 车轮 | 4 个轮速 ω_i；4 个轮胎的侧向松弛状态 |
| 执行器 | 实际转角 δ，各轮实际扭矩（或前后轴扭矩） |
| 指令缓冲 | 最近 d 步的指令（d = 最大延迟步数，例如 3） |

- 动力学对 (x, y, ψ) 平移旋转不变，网络输入完全去掉它们，只预测车身系增量，再显式积分出位姿（与 `StateSpec.integrate` 的思路相同）。
- 车辆没有人形的航向奇异问题：车身不会倒立。但翻车工况要排除，或者直接作为终止。

**动作 a**（2–5 维）：

- 基础版：转角速率指令 δ̇_cmd 加纵向加速度请求（由底层分配成驱动或制动）；
- 扩展版：转角加四轮独立扭矩（扭矩矢量控制）。动作维数越高，一阶梯度相对 PPO 的优势越明显，这是一个值得做的对照。

**ξ**（每回合采样）：

- 路面 μ（含 split-μ 和 μ 阶跃的位置与幅度）；
- 轮胎参数缩放（侧偏刚度、峰值系数）；
- 质量和质心位置（纵向、高度）、转动惯量缩放；
- 执行器延迟步数和带宽；
- 胎温（慢变量，见 §2）。

### 3.4 世界模型

- 确定性 MLP，以 (canonical(s), a, ξ) 为输入，输出车身系增量。状态维数比人形小一个数量级，起点用 3×512，再扫描宽度（InstantTrack 的经验：更小的世界模型也够用）。
- 损失：k=8 步自回归（Eq. 1），状态误差按物理量的名义尺度归一化（对应 `StateSpec.error_vector`）。
- **解析头**（不学习）：
  - 观测头：从 s 计算 IMU 量（a_x, a_y, r）、轮速、转角、相对路径的位姿；
  - 奖励头：s 对参考投影到 Frenet 坐标后计算，见 3.6；
  - 终止头：对阈值取 sigmoid 的软终止（默认），与学习式终止头做消融。
- **只学动力学 f_ω**。

### 3.5 策略与观测

部署时能拿到的量：

- IMU：r、a_x、a_y，以及横滚、俯仰角速度；
- 4 个轮速、方向盘转角；
- 定位（GNSS/RTK 或 LiDAR 定位）给出的相对路径位姿：e_y、e_ψ、s 坐标；
- v_x 的估计。

**v_y（侧偏角）和 μ 不直接给**：它们在真车上很难测，策略要从 10 帧观测历史里隐式推断。这正对应 SuperMimic 里世界模型知道 ξ、策略看不到的设定。

- 观测噪声 η 在世界模型外采样，想象时重新加上。
- **目标 g**：K≈14 个非均匀预览点。每个点给出相对当前车身系的位置、航向、v_ref，漂移参考还给出 β_ref 和 r_ref。
- 网络结构沿用编码器（预览 → 32 维潜变量）加解码器（潜变量加观测历史 → 动作），方便以后接入其他接口，比如“只给路径加速度上限”的接口。

### 3.6 奖励（解析，每步乘 Δt）

参照 SuperMimic Table A.2 的指数核写法：

| 项 | 公式 | 初始权重 |
|---|---|---|
| 横向误差 | exp(−e_y² / 0.5²) | 1.0 |
| 航向误差 | exp(−e_ψ² / 0.1²) | 1.0 |
| 速度误差 | exp(−(v − v_ref)² / 1.0²) | 1.0 |
| 侧偏角跟踪（漂移参考才启用） | exp(−(β − β_ref)² / 0.1²) | 1.0 |
| 横摆角速度跟踪 | exp(−(r − r_ref)² / 0.3²) | 0.5 |
| 动作平滑 | ‖a_t − a_{t−1}‖² | −0.1 |
| 舒适/加加速度（仅非极限参考） | ‖j‖² | −0.01 |
| 路面边界软约束 | softplus(\|e_y\| − 半路宽) | −2 |

尺度数值只是起点，在单条赛道上调好之后固定，不对每类参考单独调。

### 3.7 训练循环

与 Algorithm A.1 相同：

1. 采集：策略加动作噪声在仿真器里滚动，写入 replay buffer；
2. 拟合世界模型（k=8）；
3. 策略沿冻结的世界模型做 H 步 BPTT，用 critic 自举，并按 Eq. 3 拟合 critic。

- **控制频率与视野**：默认 50 Hz、H=32（0.64 s）。纵向需要 2–4 s 的远期信息，有两种办法：一是靠 critic 加长预览；二是降到 25 Hz、H=32（1.28 s）。两者都要扫描（§6 实验 E3）。
- **课程**：按回报重置，1 s 分桶，**直接用 `gmax_mode=remaining`**（本仓库修过的版本，避免片段尾部偏置），另外加一项“到附着极限的距离”加权：在 μ 低、侧向加速度利用率 a_y/(μg) 高的 bin 上多采样。
- **域随机化**：ξ 按回合采样；推力类扰动（侧风、单侧 μ 突变）作为 ξ 的一部分，在回合内确定地发生，世界模型可以通过 ξ 预测它们，避免了 SuperMimic 去掉推力的那个问题。

## 4. 参考与 ξ 的耦合：一个需要专门处理的问题

人形里参考动作和 ξ 基本独立：摩擦变化不会让一个走路动作变得不可行。车辆不同：一条按 μ=1.0 规划的赛车线，在 μ=0.6 时物理上就跟不住。

可选方案，按推荐顺序：

1. **参考随 ξ 生成**（默认）：路径几何固定，速度曲线按当前回合的 μ 用 g-g 图重新规划。简单，但部署时需要 μ 的估计才能生成参考。
2. **速度比例接口**：参考只给路径几何加“允许使用的附着比例” κ∈(0, 1]，速度由策略自己决定，奖励改为“沿路径前进速度 × 跟踪精度”。策略要隐式估计 μ，更接近真实赛车，但奖励不再是纯跟踪。
3. **不可行就截断**：保留原参考，跟踪误差超过阈值就终止。实现最简单，但会浪费大量回合在不可行的片段上（类比人形数据里那 452 条杂技片段）。

先用方案 1 跑通，再把方案 2 作为第二个接口（对应论文 Appendix B 的多接口训练，也对应 D7b 方向）。

## 6. 实验计划（带关卡）

| 阶段 | 内容 | 关卡（不过就停下来查） | 预计 |
|---|---|---|---|
| E0 仿真器 | 双轨 + MF 轮胎的 GPU 实现；与 CommonRoad MB 模型对拍阶跃转向、正弦停顿、稳态圆周 | 稳态侧向加速度和横摆增益误差 < 5%；吞吐 ≥ 10⁶ 步/s（单卡） | 1–2 周 |
| E1 世界模型 | 用随机加噪策略的数据拟合；8 步误差随数据量变化；**雅可比检查**：在 a_y/(μg) 分档上，比较世界模型 ∂s'/∂(s, a) 与仿真器有限差分的余弦相似度和相对幅度 | 8 步归一化误差在各档都稳定；接近饱和（> 0.9）时雅可比余弦相似度 > 0.8。不过关就先做 §8 的缓解 | 1 周 |
| E2 单赛道 | 一条赛道、固定 μ，跟踪赛车线 | 跟住整圈、e_y RMS < 0.3 m；与 NMPC 同量级 | 1 周 |
| E3 视野与频率 | H ∈ {16, 32, 64}，控制频率 ∈ {25, 50} Hz，有无 critic | 复现论文 §4.3 的结论：有 critic 时短视野够用 | 3 天 |
| E4 全库 | 全部参考 × 全部 ξ；回报重置加附着极限加权 | 训练集失败率 < 1%；记录 GPU·h 到达目标回报 | 1–2 周 |
| E5 泛化与裕度 | 三种 held-out；扰动裕度（v_y、r 冲击、μ 阶跃）；模型最坏方向与随机方向的对比（复用 `eval_margins.py` 的协议） | 报告即可，无关卡 | 1 周 |
| E6 基线 | NMPC（acados，单轨加 Pacejka，用辨识过的参数）、PPO-Sim（同样的环境、观测、奖励、网络、两倍环境数）、PPO-WM、无 critic 版本 | 同等 GPU·h 下的 time-to-quality 曲线；推理耗时（策略 µs 级 vs NMPC ms 级） | 1 周 |
| E7（可选）真车 | 1:10 平台（F1TENTH 类）或 HIL；用真实数据微调 ξ 或世界模型（论文 §6 提出的系统辨识方向） | — | 视资源 |

主训练（E4）的算力粗估：车辆仿真比人形便宜，世界模型也小一个数量级，单卡 H100 级别几个小时应该能跑完一次。这是估计，E2 跑完后再根据实测修正。

## 7. 研究问题（写成论文时的主线）

1. **RQ1 摊销**：一个世界模型能否覆盖所有赛道、机动和整个 μ 区间？参考库从 10² 条扩到 10⁴ 条时，误差和到达目标回报的 GPU·h 怎样变化（对应论文 Fig. 3b/c）？
2. **RQ2 极限处的梯度**：轮胎饱和区的世界模型雅可比可靠吗？BPTT 相对 PPO 的优势，在线性区和饱和区分别有多大？
3. **RQ3 接近极限的程度**：同等算力下，策略对附着的利用率（a_y/(μg) 的分布、圈速）能否接近 NMPC？失控次数比较如何？
4. **RQ4 隐式 μ 估计**：不给 μ，仅凭观测历史，策略在 μ 阶跃和 split-μ 下能否保持稳定？
5. **RQ5 可微系统辨识**：用世界模型对 ξ 的梯度，从几秒真实或仿真数据里在线估计 μ，精度和收敛速度如何？

## 8. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 饱和区雅可比不准（C4） | E1 余弦相似度低；策略不敢逼近极限，或者逼近后失控 | 按饱和程度给世界模型损失加权；在饱和区加采样（D1）；集成模型，用方差惩罚；必要时混合：学来的模型做前向，简化可微模型求梯度（DMO / Song et al. 的思路） |
| 超过极限后混沌（打滑甩尾） | 梯度爆炸，训练发散 | 软存活权重本来就会截断失控后的贡献；梯度裁剪（论文的两级裁剪）；必要时用自适应视野 |
| 不可微逻辑（ABS/ESC、换挡） | 世界模型在门限附近误差高 | 先关掉，确认基础版可行后再打开，作为“黑盒兼容性”的专门实验 |
| 参考与 ξ 不一致 | 大量回合浪费在不可行的参考上 | §4 方案 1；可行性预过滤 |
| 观测不足（v_y、μ） | 策略在低 μ 上不稳定 | 观测历史；可以加一个辅助的 v_y 估计头（自监督，监督信号来自仿真器） |
| 仿真到实车 | 轮胎模型偏差 | ξ 覆盖轮胎参数；真实数据精修世界模型（E7）；先在 1:10 平台验证 |
| 安全 | 学来的模型没有保证 | 只把裕度和最坏方向作为测试工具；真车实验加安全控制器兜底 |

## 9. 第一步具体做什么（两周内）

1. 重构：`StateSpec` 接口化 ✅（见 §5 进度）；`AnalyticHeads`、想象 rollout 和裕度工具接口化，G1 回归测试通过。
2. 写双轨 + MF 轮胎的 GPU 仿真器，并与 CommonRoad MB 模型对拍（E0）。
3. 生成一条赛道 × 3 个 μ 的参考，跑通 E1 的雅可比检查。**E1 的结论决定这个方向值不值得继续**：如果饱和区雅可比完全不可靠，就优先研究 §8 第一行的缓解，而不是直接上全库训练。
