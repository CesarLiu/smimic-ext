# 提案：SuperMimic for Vehicles：用一个可微世界模型学车辆极限操控

状态：E0 仿真器、端到端 demo、E1 检查和极限附近的策略学习（第 2 步）已实现（§3.1、§3.8、§3.9、§3.10）；按什么顺序运行、怎么读结果见 [`VEHICLE_RUNBOOK.md`](VEHICLE_RUNBOOK.md)。它是 [`RESEARCH_DIRECTIONS.md`](RESEARCH_DIRECTIONS.md) §6.5 的展开版。

一句话：把 SuperMimic 的配方原样搬到车辆上。用一个确定性世界模型学同一辆车在所有工况下共享的动力学，数据来自不可微的高保真车辆仿真器；策略沿世界模型做短视野 BPTT 加 critic，在一个大型参考轨迹库上学会跟踪，并把训练集中到附着极限附近。

## 1. 为什么车辆极限操控是好的迁移目标

按 `RESEARCH_DIRECTIONS.md` §6.1 的六个条件逐条对照：

| 条件 | 人形跟踪 | 车辆极限操控 | 判断 |
|---|---|---|---|
| C1 动力学跨任务共享 | 所有动作共享一个身体 | 所有轨迹、赛道、机动共享一辆车 | ✓ 完全同构 |
| C2 奖励可微、可解析 | 经 FK 的跟踪奖励 | 经 Frenet 投影的跟踪奖励（横向误差、航向误差、速度误差） | ✓ 比人形还简单，不需要 FK |
| C3 状态结构化 | 约 70 维 | 约 25–35 维 | ✓ |
| C4 动力学光滑 | 接触切换 | 轮胎饱和；ABS/ESC、换挡等逻辑不连续 | △ **主要风险**，见 §8 |
| C5 便宜的数据源 | GPU 并行刚体仿真 | GPU 并行双轨模型 + Pacejka 轮胎，易达 10⁶ 步/s 量级 | ✓ |
| C6 短视野 + critic 足够 | 0.64 s 覆盖动作瞬态 | 横摆/侧向瞬态 0.1–1 s；纵向（入弯前刹车）需要 2–4 s | △ 需要更长的参考预览，H 需要扫描 |

另外两项加分：

- 高保真车辆仿真器（多体模型、MF 6.x 轮胎、ESC 逻辑）大多**不可微**，正是“从黑盒仿真器日志学可微代理”的用武之地；
- 现有的学习式赛车/漂移控制要么是模型无关 RL，算力很大（GT Sophy，Nature 2022；Fuchs et al., RA-L 2021），要么是 NMPC（Kabzan et al., RA-L 2019 的学习式 MPC；Goh & Gerdes 的漂移控制）。“单卡小时级、一个策略覆盖上万条轨迹和整个摩擦区间”的位置是空着的。

与已有可微驾驶工作的区别：

- Waymax 上的 APG（Nachkov et al., IROS 2025）和 Dream to Drive / Analytic World Models（AAAI 2026）用的是**解析可微的运动学模型**，没有轮胎，也不涉及极限工况；
- Song, Kim & Scaramuzza（CoRL 2025）在四足上用简化可微代理求梯度，再用高保真仿真器做前向。本提案对应的是“**学**出来的代理，加车辆极限工况”。

## 2. 对 §6.5 原稿的修正

| 原稿 | 问题 | 修正 |
|---|---|---|
| “失控（横摆角或侧偏角超限）作为终止” | 漂移本身就是大侧偏角，按绝对值终止会把漂移参考全部判成失败 | 终止相对**参考**定义，与 SuperMimic 的“根部相对参考偏离”一致：\|e_y\| > 阈值、\|e_ψ\| > 阈值、\|β − β_ref\| > 阈值，或驶出路面边界 |
| “ξ 包含执行器延迟” | 延迟不是一个可以在每步动力学里查到的参数：系统状态必须包含尚未生效的指令，否则不满足马尔可夫性 | 把动作缓冲（最近 d 步指令）放进状态 s；ξ 里只放延迟的**步数**，用来选择缓冲的读出位置 |
| “从真实驾驶日志和赛车线生成参考轨迹” | 同一条参考在 μ=1.0 时可行，在 μ=0.5 时不可行。人形的“可行性过滤”在这里和 ξ 耦合 | 参考按 ξ 生成：路径几何不变，速度曲线由 g-g 图（随 μ 缩放）重新规划；或者参考只给路径几何加“目标速度比例”，见 §4 |
| “以未来 K 个参考点为目标” | 原稿默认 K 个时间步，50 Hz 下 K=10 只预览 0.2 s，不够入弯前刹车 | 用**空间或时间不均匀采样**的预览：近处密、远处疏，覆盖约 3 s（例如 0.1, 0.2, …, 1.0, 1.5, 2.0, 3.0 s，共 K≈14） |
| “失控作为学习式终止头” | 终止是状态和参考的确定性函数，学出来反而引入误差 | 默认用**解析**的软终止（对阈值取 sigmoid），并与学习式终止头做消融 |
| 胎温进入状态 | 胎温变化的时间常数是几十秒，远超 H，在想象窗口里几乎是常数 | 胎温放进 ξ 的“慢变量”部分，每回合随机初始化，只在仿真器里演化；世界模型以当前值为条件，不预测它 |

## 3. 系统设计

### 3.1 仿真器（数据源）

#### 为什么不直接用 MuJoCo

- **MuJoCo 没有轮胎模型。**它的轮地接触就是刚体加摩擦锥。轮胎力随侧偏角、滑移率增长并饱和、组合滑移、松弛长度，这些都不在模型里。用它算出来的极限是摩擦锥的极限，不是 Pacejka 曲线的极限；本提案研究的恰好是附着极限附近的轮胎饱和（E1 的关卡就在这里）。
- **状态维数和成本不划算。**双轨模型加悬架简化和轮速，约 17–30 维，一步只有几十个逐元素运算。整套刚体接触求解器贵得多，又换不来需要的那部分保真度。
- **不可微逻辑要自己控制。**ABS/ESC 门限、μ 阶跃等要能逐个开关做消融。
- **代价**：用不上 mjlab 现成的环境管理和回放记录，需要为车辆单写一个环境。前面的接口化重构（`StateSpec`、`AnalyticHeads`、任务接口、`NetIO`、裕度工具）就是为此准备的，学习端已不依赖 mjlab。
- **折中方案（以后要三维地形、复杂悬架时）**：MuJoCo 负责车身和悬架的多体动力学，每个子步由自己的 kernel 按 Pacejka 算轮胎力并写入外力，可以复用 mjlab，但实现复杂。平路极限操控阶段用不上。

#### 为什么用 CommonRoad 核对，而不是 GPUDrive 或 Waymax

| | 定位 | 车辆动力学 | 在本提案里的用处 |
|---|---|---|---|
| **CommonRoad 车辆模型**（`commonroad-vehicle-models`，BSD） | 运动规划基准，附带从点质量到多体模型的一组公开车辆动力学参考实现 | 多体模型 29 个状态，含悬架、非簧载质量、轮胎垂向刚度和 PAC2002 型组合滑移轮胎，带具体车型参数 | **动力学参照**：对拍稳态、阶跃、正弦、加速、制动、弯中制动 |
| **Waymax** | 基于 Waymo Open Motion Dataset 的多智能体交通仿真，JAX，可微 | 运动学自行车模型 / 位移增量模型，没有轮胎 | 不能做动力学参照；可作真实驾驶参考轨迹来源，或用于以后的规划层方向（§6.2-C） |
| **GPUDrive** | 同样基于 Waymo Open Motion Dataset 的大规模 GPU 多智能体仿真，主打吞吐 | 同样是运动学层面的模型，没有轮胎 | 同上 |

Waymax 和 GPUDrive 解决的是“很多车在真实路网里怎样交互”，本提案要解决的是“一辆车在附着极限怎样动”。前者的车辆模型恰好把后者抽象掉了：运动学自行车模型里轮胎永远不打滑。

CommonRoad 的局限：
- 它只是公开、可复现的**参考实现**，不是真值，说明的是“和一个公认的多体轮胎模型一致”，不是“和真车一致”；
- 它在 CPU 上用 Python 运行，只适合离线对拍。

要证明与真车一致，需要实车测量或 CarMaker、VI-grade 一类商业工具（E7）。方法只需要仿真器的日志，所以数据源可以替换；硬约束是吞吐：论文的收益建立在大量并行采样上。

#### 实现（E0，`src/supermimic/vehicles/`）

- **参数**（`params.py`）：默认就是 CommonRoad 车辆 2（BMW 320i）：质量、几何、悬架、轮胎参数逐项相同（有测试核对）。
- **轮胎**（`tire.py`）：CommonRoad 的 PAC2002 公式逐项搬到 torch 上，纯滑移 + 组合滑移 + 外倾，另加路面摩擦缩放和滑移刚度缩放（ξ）。在 567 个工况点上与 CommonRoad 完全相同。
- **动力学**（`dynamics.py`，17 维状态）：
  - 车身平面运动和横摆；
  - 侧倾和俯仰两个二阶自由度，带重力失稳项，产生动态载荷转移。每轴侧倾刚度 = 悬架（弹簧 + 辅助扭转）与轮胎垂向刚度串联；
  - 非簧载质量的准静态载荷转移；
  - 由侧倾和俯仰得到的外倾；
  - 四个车轮的自旋自由度，半隐式积分（滑移方程是刚性的）；
  - CommonRoad 的转向和加速度约束、扭矩分配；
  - 可开关的 ABS（单轮按滑移率释放，带滞回）和 ESC（按横摆角速度误差单轮制动，带滞回）。

  控制周期 50 Hz，每步 10 个子步。车轮编号沿用 CommonRoad 多体模型的约定：它的 “LF/LR” 轮位于 y = −T/2，即左转的外侧。
- **未包含**（相对原计划）：松弛长度、离散换挡（CommonRoad 多体模型也没有；以后加的话要另找参照）、垂向跳动和柔性铰。
- **对拍结果**（`python -m supermimic.vehicles.validation`，float32，10 子步，ABS/ESC 关闭）：14 个工况的全部指标都在 5% 以内，最差一项 4.08%（正弦 0.07 rad、接近极限时的侧向加速度 NRMSE）：

  | 工况 | 指标 | 结果 |
  |---|---|---|
  | 稳态转弯（7 个，ay 1.8–7.1 m/s²） | 末段横摆角速度 / 侧向加速度相对误差；全程 NRMSE | ≤ 0.2%；r ≤ 0.3%，ay ≤ 1.9% |
  | 阶跃转向（0.03 / 0.06 rad，后者 ay 8.7 m/s²） | 峰值横摆角速度；NRMSE | ≤ 0.2%；r ≤ 0.9%，ay ≤ 1.9% |
  | 正弦转向（0.04 / 0.07 rad） | 峰值横摆角速度；NRMSE | ≤ 0.9%；r ≤ 2.2%，ay ≤ 4.1% |
  | 加速、制动 | 车速 NRMSE；速度变化量相对误差 | ≤ 1.0%；≤ 2.8% |
  | 弯中制动 | NRMSE | r 2.2%，ay 2.1% |

  另外：
  - 子步数从 10 增加到 40，结果变化 < 1%（已收敛）；
  - float32 与 float64 结果相同；
  - 稳态侧偏角相差 ≤ 0.15°，侧倾角相差 ≤ 0.5°（这两项不计入门槛）。
- **ABS / ESC 的效果**（测试中验证）：
  - μ = 0.5 紧急制动：制动距离缩短 30% 以上；制动时仍能转向。
  - 超出附着极限的正弦转向：ESC 把峰值侧偏角降到不开时的 60% 以下。
- **环境**（`env.py`）：
  - 执行器：指令延迟、转向伺服加速率限制、纵向一阶响应；
  - 每回合采样 ξ（路面摩擦、轮胎刚度、质量、质心位移、延迟步数）；
  - 跟踪奖励和终止相对参考定义（`tracking.py`）；
  - 回放记录与 G1 记录器相同（转移行 + 带终止标签的终止行）；
  - 起点由 `ReturnBasedResetSampler` 在参考轨迹的布局上采样。

  参考轨迹由同一套执行器和动力学在名义 ξ 下用脚本驾驶员生成，只保留稳定的轨迹（侧偏角 < 7°、车速 > 4 m/s）；回放其指令能完全复现参考（奖励达到上限的 99.9% 以上）。低摩擦下部分参考不可行，目前按 §4 方案 3 直接终止。
- **吞吐：GPU 门槛（≥ 10⁶ 步/s）通过 ✅**。在单张 H200 上用 `scripts/vehicle/bench_sim.py` 实测（2026-11-04，10 子步，float32）：

  | 环境数 | eager 动力学 | eager 完整环境 | compile 动力学 | compile 完整环境 |
  |---|---|---|---|---|
  | 4096 | 1.3×10⁵ | 1.2×10⁵ | 5.9×10⁶ | 8.4×10⁵ |
  | 16384 | 5.3×10⁵ | 4.6×10⁵ | 2.3×10⁷ | 3.3×10⁶ |
  | 65536 | 2.1×10⁶ | **1.9×10⁶** | 9.2×10⁷ | **1.3×10⁷** |

  单位是步/秒。“完整环境”含执行器、奖励、终止、回放写入和重置。
  - 不 compile 时，65536 个环境就过门槛；compile 后高一个数量级，16384 个环境也过。
  - eager 下吞吐几乎与环境数成正比，说明瓶颈是逐元素算子的启动开销，不是计算量。
  - compile 后动力学比完整环境快约 7 倍，此时瓶颈在环境的记账逻辑（回放写入、重置）。E4 若需要更高吞吐，先优化这部分。

  CPU（4 核）参照：16384 个环境时，eager 动力学约 1.4×10⁵、环境约 1.2×10⁵；compile 时分别约 2.2×10⁵ 和 1.7×10⁵。

### 3.2 参考轨迹库（对应动作库）

| 来源 | 内容 | 规模（目标） |
|---|---|---|
| 赛道 | 公开赛道中心线和边界（例如 TUMFTM 的 racetrack-database），最小曲率或最短时间赛车线（例如 TUMFTM 的 global_racetrajectory_optimization），按多个 μ 和速度比例重新规划速度曲线 | 约 20 条赛道 × 10 个 μ × 5 个速度比例 → 切成 10–20 s 的片段，数万条 |
| 标准机动 | ISO 3888-1/-2 双移线、麋鹿测试、正弦停顿、阶跃转向、开环 J-turn，覆盖不同速度和 μ | 数千条 |
| 真实驾驶日志 | highD、nuPlan 等的自车轨迹（正常工况，用于覆盖低激励区） | 数千条 |
| 漂移 | 用非线性最优控制（例如 acados 加单轨模型）生成稳态漂移平衡点和漂移过渡段，参考同时给出 β_ref、r_ref | 数千条 |

**可行性**：每条参考连同 ξ 一起，先在仿真器里用一个强基线（NMPC 或 PPO 教师）试跑，跟不住的标为不可行，不进训练库（对应 BONES-SEED 的可行性过滤）。也可以只做 g-g 包络检查（|a| ≤ μ·g·安全系数），作为便宜的近似。

**Held-out 划分**（从第一天就固定）：

- `heldout_track`：整条赛道留出；
- `heldout_maneuver`：整类机动留出（例如训练不含麋鹿测试）；
- `heldout_mu`：μ 区间外推，例如训练 μ∈[0.4, 1.1]，测试 0.3 和 1.2。

### 3.3 状态、动作、ξ

**状态 s**（约 30 维，航向规范化）：

| 组 | 量 |
|---|---|
| 位姿 | x, y, ψ（世界系；网络输入只用航向规范化后的量，见下） |
| 车身速度 | v_x, v_y, r（车身系），侧倾角 φ、俯仰角 θ 及其角速度，垂向位移和速度 |
| 车轮 | 4 个轮速 ω_i；4 个轮胎的侧向松弛状态 |
| 执行器 | 实际转角 δ，各轮实际扭矩（或前后轴扭矩） |
| 指令缓冲 | 最近 d 步的指令（d = 最大延迟步数，例如 3） |

- 动力学对 (x, y, ψ) 平移旋转不变，网络输入完全去掉它们，只预测车身系增量，再显式积分出位姿（与 `StateSpec.integrate` 的思路相同）。
- 车辆没有人形的航向奇异问题：车身不会倒立。但翻车工况要排除，或者直接作为终止。

**动作 a**（2–5 维）：

- 基础版：转角速率指令 δ̇_cmd 加纵向加速度请求（由底层分配成驱动或制动）；
- 扩展版：转角加四轮独立扭矩（扭矩矢量控制）。动作维数越高，一阶梯度相对 PPO 的优势越明显，这是一个值得做的对照。

**ξ**（每回合采样）：

- 路面 μ（含 split-μ 和 μ 阶跃的位置与幅度）；
- 轮胎参数缩放（侧偏刚度、峰值系数）；
- 质量和质心位置（纵向、高度）、转动惯量缩放；
- 执行器延迟步数和带宽；
- 胎温（慢变量，见 §2）。

### 3.4 世界模型

- 确定性 MLP，以 (canonical(s), a, ξ) 为输入，输出车身系增量。状态维数比人形小一个数量级，起点用 3×512，再扫描宽度（InstantTrack 的经验：更小的世界模型也够用）。
- 损失：k=8 步自回归（Eq. 1），状态误差按物理量的名义尺度归一化（对应 `StateSpec.error_vector`）。
- **解析头**（不学习）：
  - 观测头：从 s 计算 IMU 量（a_x, a_y, r）、轮速、转角、相对路径的位姿；
  - 奖励头：s 对参考投影到 Frenet 坐标后计算，见 3.6；
  - 终止头：对阈值取 sigmoid 的软终止（默认），与学习式终止头做消融。
- **只学动力学 f_ω**。

### 3.5 策略与观测

部署时能拿到的量：

- IMU：r、a_x、a_y，以及横滚、俯仰角速度；
- 4 个轮速、方向盘转角；
- 定位（GNSS/RTK 或 LiDAR 定位）给出的相对路径位姿：e_y、e_ψ、s 坐标；
- v_x 的估计。

**v_y（侧偏角）和 μ 不直接给**：它们在真车上很难测，策略要从 10 帧观测历史里隐式推断。这正对应 SuperMimic 里世界模型知道 ξ、策略看不到的设定。

- 观测噪声 η 在世界模型外采样，想象时重新加上。
- **目标 g**：K≈14 个非均匀预览点。每个点给出相对当前车身系的位置、航向、v_ref，漂移参考还给出 β_ref 和 r_ref。
- 网络结构沿用编码器（预览 → 32 维潜变量）加解码器（潜变量加观测历史 → 动作），方便以后接入其他接口，比如“只给路径加速度上限”的接口。

### 3.6 奖励（解析，每步乘 Δt）

参照 SuperMimic Table A.2 的指数核写法：

| 项 | 公式 | 初始权重 |
|---|---|---|
| 横向误差 | exp(−e_y² / 0.5²) | 1.0 |
| 航向误差 | exp(−e_ψ² / 0.1²) | 1.0 |
| 速度误差 | exp(−(v − v_ref)² / 1.0²) | 1.0 |
| 侧偏角跟踪（漂移参考才启用） | exp(−(β − β_ref)² / 0.1²) | 1.0 |
| 横摆角速度跟踪 | exp(−(r − r_ref)² / 0.3²) | 0.5 |
| 动作平滑 | ‖a_t − a_{t−1}‖² | −0.1 |
| 原始动作越界（实现中加入，§3.10） | Σ max(\|a\| − 2.5, 0)² | −1 |
| 舒适/加加速度（仅非极限参考） | ‖j‖² | −0.01 |
| 路面边界软约束 | softplus(\|e_y\| − 半路宽) | −2 |

尺度数值只是起点，在单条赛道上调好之后固定，不对每类参考单独调。

### 3.7 训练循环

与 Algorithm A.1 相同：

1. 采集：策略加动作噪声在仿真器里滚动，写入 replay buffer；
2. 拟合世界模型（k=8）；
3. 策略沿冻结的世界模型做 H 步 BPTT，用 critic 自举，并按 Eq. 3 拟合 critic。

- **控制频率与视野**：默认 50 Hz、H=32（0.64 s）。纵向需要 2–4 s 的远期信息，有两种办法：一是靠 critic 加长预览；二是降到 25 Hz、H=32（1.28 s）。两者都要扫描（§6 实验 E3）。
- **课程**：按回报重置，1 s 分桶，**直接用 `gmax_mode=remaining`**（本仓库修过的版本，避免片段尾部偏置），另外加一项“到附着极限的距离”加权：在 μ 低、侧向加速度利用率 a_y/(μg) 高的 bin 上多采样。
- **域随机化**：ξ 按回合采样；推力类扰动（侧风、单侧 μ 突变）作为 ξ 的一部分，在回合内确定地发生，世界模型可以通过 ξ 预测它们，避免了 SuperMimic 去掉推力的那个问题。

### 3.8 端到端 demo（`scripts/vehicle/demo_e2e.py`）

整条 SuperMimic 循环在车辆上跑通，学习端用的是与 G1 完全相同的代码（`WorldModel`、`WorldModelTrainer`、`imagine`、`PolicyTrainer`、`NetIO`）。车辆只通过三个接口接入，实现在 `src/supermimic/vehicles/learner.py`：

- **`VehicleStateSpec`**：环境记录的 29 维状态。网络输入去掉位姿；位姿由预测的车身速度显式积分。转向角、纵向执行器状态和待执行指令是动作和 ξ 的已知函数，通过新的可选接口 `StateSpecBase.step_known` 精确给出，不交给网络学。G1 不实现这个接口，行为不变。
- **`VehicleHeads`**：观测、奖励、终止特征直接复用环境的 `tracking.py` 和观测定义，所以想象中的打分与环境完全一致（`tests/test_vehicle_e2e.py` 逐转移核对）。辅助输出是位姿，供目标预览使用。
- **`VehicleTask`**：参考轨迹和目标预览（`env.preview_goal`，与环境共用）。

流程：
1. 生成训练参考库（32 条 × 500 步）和另一套种子的**留出**参考库（16 条）；
2. 256 个环境用当前策略加探索噪声采集，ξ 随机化，起点由按回报的重置采样器给出；
3. 先单独训练世界模型（第 100 次迭代起），再开始训练策略和 critic（第 300 次迭代起，16 步想象 BPTT）；
4. 训练前后各在仿真器里确定性地评估一次：名义 ξ、无噪声、留出参考、从每条参考的开头跑完整条。

为了让这个流程稳定，还做了三处改动：

- **执行器指令用 tanh 限幅**，环境和世界模型共用 `env.actuator_update`。动作变化惩罚也按限幅后的指令计算，所以有界。否则策略会把动作推得很大，状态跑出世界模型见过的分布。（这还不够：tanh 之前的原始动作仍会漂移，§3.10 又加了截断和越界惩罚。）
- **critic 估值截断**：`PolicyTrainerCfg.value_clip`，默认关闭；demo 设为折扣回报的上限 `max_step_reward / (1 − γ)`，critic 特征也做了归一化截断。不截断时，critic 用自己的估值做自举，在分布外的想象状态上自我放大（估值涨到 10⁶ 量级），再经 V(s_H) 把策略带崩。
- **世界模型先行**：策略晚于世界模型 200 次迭代开始学习。

结果（种子 0，CPU 4 核，约 8 分钟，可复现；报告见 `docs/results/vehicle_demo_e2e.json`）。表中“当前”一列是加入 §3.10 的原始动作约束之后的结果；“首次”一列是加入之前的结果，留作对照：

|---|---|---|---|
| 归一化回报（整条参考的满分为 1） | 0.104 | **0.356** | 0.623 |
| 平均坚持步数（满分 499） | 86 | **254** | 441 |

世界模型最终的 8 步归一化误差为 0.25（在最近的回放数据上）。

- E1 要求的饱和区雅可比检查还没有做。

### 3.9 E1：饱和区雅可比检查（`scripts/vehicle/jacobian_check.py`）

**问题**：策略梯度要穿过世界模型的雅可比。接近附着极限时，真实灵敏度会急剧变化：继续加转向，侧向加速度不再增加。这正是学来的模型最可能误导策略的地方（§8 第一条风险）。

**做法**（`src/supermimic/vehicles/jacobian.py`）：
- **数据**：ABS/ESC 关闭（门限逻辑没有可比的导数），路面摩擦随机化，范围 0.5–1.1；行为策略是“参考指令 + 噪声”，让数据覆盖并越过附着极限。离线训练世界模型。
- **评估样本**：在另一套留出参考上采集。按附着利用率 u = √(a_x² + a_y²) / (μg) 分 6 档，每档约 60 个状态。
- **仿真器侧**：float64 中心差分，与环境走同一条“执行器 + 动力学”的单步函数（`logged_step`，测试中与环境逐位相等）。每个状态用两种步长各算一次，两次不一致的（落在不可微点上）排除并计数，约 1–5%。**世界模型侧**：自动求导。两边都换算成归一化误差单位。
- **比较的量**：
  - 单步：状态变化量 s' − s 的雅可比。只比网络预测的行（速度、横摆、姿态、轮速、加速度）；位姿是显式积分的，执行器状态是精确计算的，算进来会虚高。列是动态状态，加上本步生效的指令：有延迟时，生效的是待执行指令里 d 步前的那一条。
  - 8 步：8 步后的状态对第一步动作的梯度，即 BPTT 实际用的量。
  - 关键灵敏度：转向 → 侧向加速度 / 横摆角速度 / 侧向速度，油门 → 车速。只在仿真器值不可忽略的样本上统计：这台车的转向速率上限只有 0.4 rad/s，伺服顶在速率上限时，这一步对指令的导数恰好为零。

**结果**（种子 0，CPU；报告见 `docs/results/vehicle_jacobian_check.json` 与 `..._large.json`）：

|---|---|---|---|---|---|---|
| 0.0–0.3 | 0.126 / 0.015 | 0.46 / 0.57 | 0.54 / 0.60 | 0.93 / **0.99** | 1.01 | 100%（17） |
| 0.3–0.6 | 0.111 / 0.017 | 0.48 / 0.56 | 0.45 / 0.57 | 0.94 / **0.99** | 1.00 | 100%（19） |

两个配置：
- 默认：256×256，采集 1000 步，4000 次更新，约 4 分钟；
- 大容量：512×512，采集 1500 步，12,000 次更新，约 17 分钟。

**按原定关卡：未通过**，两项都不过：
- 8 步误差在饱和区升到线性区的 5 倍（默认）和 11 倍（大容量），超过“最多 3 倍”；
- 饱和区单步雅可比余弦中位数为 0.52（默认）和 0.60（大容量），低于 0.8。

**结论**：
1. **BPTT 真正用的多步梯度在饱和区是可靠的**，前提是给世界模型足够的容量和训练量。大容量模型的 8 步动作梯度：接近极限时余弦 0.95，越过极限时 0.92，幅值比 1.04–1.09。默认规模下越过极限只有 0.71。这是“容量和训练量”问题，不是方法本身的问题。
2. **单步雅可比逐元素不准，加大容量也几乎不改善**（0.5 → 0.6）。速度组随利用率单调变差，到饱和区只有 0.29。轮速组在默认规模下几乎没学到（0.1–0.3），大容量下到 0.35–0.6。用 8 步自回归损失训练的 MLP，单步局部导数逐项不对，但组合成多步梯度时是对的。
3. **饱和区的一阶灵敏度方向开始出错**：转向 → 侧向加速度的符号一致率从线性区的 100% 降到饱和区的约 70%。这一项有效样本少（12–22 个），结论只是方向性的。
4. **8 步误差绝对值大幅下降，但相对饱和区的比值反而变大**：大容量模型在越过极限后的误差（0.16）低于默认模型在线性区的误差（0.13）。“相对线性区不超过 3 倍”可能不是合适的判据形式。

**关卡修订（2026-11-04 确认采用）**：
- 雅可比关卡改为：u > 0.9（两档合并）时 **8 步动作梯度**余弦的中位数 > 0.8。这是策略更新实际用的量；
- 误差关卡改为绝对值：u > 0.9 时 8 步误差的平均值 < 0.2；
- 单步雅可比继续报告，只作诊断，不再是门槛。

实现在 `jacobian.e1_gate`。上面两次运行由固定种子得到、可复现，按记录的指标重新判定（报告的 `gate` 字段里保留了原判定）：

|---|---|---|---|
| 默认 | 0.800 | 0.551 | ❌ 未通过（误差；余弦恰在边界） |
| 大容量 | 0.943 | 0.115 | ✅ **通过** |

**E1 在大容量配置下通过。**之后的车辆世界模型默认用大容量配置。

**局限**：
- 单种子，每档约 60 个样本；
- ABS/ESC 关闭，开启时的梯度质量没测；
- 世界模型是离线训练的，没有在策略训练循环里检查；
- “梯度方向对”不等于“策略能在极限附近学好”，后者要靠 E3/E4 验证。

**下一步**（§8 的缓解措施，按代价从低到高）：
- 对饱和区样本加权或过采样世界模型损失；
- 对速度组单独加大损失权重；
- 小集成，用方差作为不确定性惩罚；
- 在 E4 的策略训练里直接比较大小两种世界模型下，策略在极限附近的表现。

### 3.10 第 2 步：策略能否在附着极限附近学好（`scripts/vehicle/limit_study.py`）

E1 回答的是“梯度对不对”，这一步回答“策略能不能在极限附近学好”，并在策略训练里直接比较大小两种世界模型。

**设置**（默认参数，种子 0，CPU 约 23 分钟）：
- **参考按摩擦生成**（§4 方案 1）：μ ∈ {0.5, 0.8, 1.0} 三档，每档 12 条训练参考、6 条留出参考，每条 500 步（10 s）。侧向加速度峰值取 μg 的 40–95%，所以参考对它的摩擦是可行的。训练参考里 8.2% 的步用到 80% 以上的摩擦（“近极限”）。
- 训练回合的摩擦等于参考的摩擦（`match_friction`）；轮胎刚度、质量、质心和延迟照常随机化。ABS/ESC 关闭（与 E1 相同），只能靠策略自己守住附着。
- 两种世界模型：小（256×256，即 E1 的默认规模）和大（512×512，E1 通过的配置）。其余设置与 §3.8 的 demo 相同，各训练 2500 次迭代。
- 评估：每档 6 条留出参考，从起点开始确定性地跑完整条，用参考自己的摩擦，其余 ξ 取标称值。近极限指标只看参考上利用率 > 0.8 的步（每档 232–507 步，分母对两个模型相同）：“仍在参考上的比例”和这些步上的误差。

**先修了一个发散问题。**第一次完整运行时，小模型在约 1250 次迭代、大模型在约 1750 次迭代时，世界模型误差和 critic 爆掉（8 步误差到 10³–10²⁰），随后重置采样器因 NaN 回报崩溃。逐步诊断回放数据后找到根因：
- 动作经 tanh 压缩后才进执行器。tanh 饱和后，奖励对原始动作几乎没有梯度，没有任何东西把它拉回来；
- 在极限附近，策略的原始输出一路漂移（转向约 97，加速度约 318，见于第 1350 次迭代）；
- 这些原始值作为“待执行指令”进入状态，又作为动作输入进入世界模型，远在训练分布之外。

修正（提交 6364220）：
- 奖励加一项解析的 `action_bound`，惩罚 |a| > 2.5 的部分。这一项在想象里可微，给策略一个往回拉的梯度；
- 执行器保存指令前把原始动作截到 ±3（tanh(3) = 0.995）。环境和世界模型的 `step_known` 用同一个函数，所以状态有界；
- 仿真器一步出现非有限值时，以最后一个有限状态终止该回合（只在远超任何终止阈值的状态下才会发生）；
- 重置采样器忽略非有限回报。

修正后，两种模型都稳定跑完 2500 次迭代：最终 8 步误差 小 0.18、大 0.10，critic 损失 0.1–0.3。

**结果**。同一命令、同一种子，在两台机器上各跑了一次。两次的参考和训练前的策略完全相同（“训练前”一行逐位一致），但训练过程在早期就分叉了（大模型第 1000 次迭代时，8 步误差分别为 0.56 和 0.82），最终得到不同的策略。所以这两次运行可以看作两个独立样本。

- 所以，**单次运行的数字差异很大**：同一模型、同一档摩擦，两次的回报相差可达 0.21，近极限仍在参考上的比例相差可达 48 个百分点（小模型，μ=1.0：12% 对 60%）。

**结论**（按两次运行修订）：
1. **策略能在附着极限附近学会跟踪**，三档摩擦都是，包括 μ=0.5 的低附着路面。两次运行的回报都从约 0.1 升到 0.38–0.76；近极限仍在参考上的比例从 0–12% 升到 12–100%。
2. **大世界模型在两次运行中都不差于小模型**：
   - 12 个对比项（2 次运行 × 3 档摩擦 × 回报和近极限比例两项）里，大模型 11 项更好、1 项持平；
   - 回报高 0.02–0.15；近极限仍在参考上的比例高 0–47 个百分点。

   方向与 E1 一致：小模型在饱和区的 8 步误差 0.55 不过关，大模型 0.12 过关。但差距的大小不可靠，同一模型两次运行之间的波动与两模型之间的差距同量级。运行 A 里“μ=1.0 时是 4 倍”这类说法不成立。此后车辆实验默认用大世界模型；要定量说明差距有多大，需要多种子。
3. **失效的方式像是横向跑偏，不是失稳**。运行 A 中，近极限时航向误差 0.02–0.10 rad、侧偏误差 < 0.03 rad，车身是稳的；两次运行的近极限横向误差都在 0.44–0.90 m，与 σ_lat = 0.5 m 同量级。这看起来像“推头、跑宽”，即策略在极限附近偏保守或偏晚；各终止原因的占比还没有统计。近极限横向误差只在策略撑过的步上平均，撑得更久的策略会在更难的段上被计入，所以这一项不适合直接比较两个模型。
4. **离 E4 的关卡还很远**。运行 A 中，大模型的终止率仍有 33–50%，E4 要求训练集失败率 < 1%。两次都只在 CPU 上训练了 2500 次迭代，256 个并行环境。

**局限**：
- 只有两个样本（同一种子、两台机器），波动很大；每档只有 6 条留出参考，终止率的分辨率是 1/6；
- 训练很短，两种模型都还在上升，差距在更长训练下可能缩小或扩大；
- ABS/ESC 关闭；
- 只比较了世界模型容量，没有比较 E1 的其他缓解措施（饱和区加权、速度组加权、集成）。

**下一步**：
- 加长训练（GPU），看终止率能否降到 E4 的量级，以及大小模型的差距是否保持；
- 针对横向跑偏：对近极限样本加权世界模型损失（§3.9 的缓解 1），或给策略更长的预览；
- 多种子，更多留出参考；
- 之后进入 E3（视野与频率）和 E4（全库）。

### 3.11 S 弯 demo：SuperMimic 对比 PPO（`scripts/vehicle/compare_ppo.py`）

**设定**：
- 两种方法在同一个随机弯道库上训练（与 §3.10 相同：三档摩擦，侧向加速度峰值 40–95% μg，ABS/ESC 关）；
- 测试用留出弯道，以及一条训练里没见过的 S 弯：15 m/s，弧上 0.7μg，实际附着利用率最高 0.97，每档摩擦一条；
- 环境、观测、奖励、终止、ξ 随机化和网络结构都相同。PPO 的 actor 就是 SuperMimic 的 `Policy`，外加一个可学的动作标准差；critic 就是 SuperMimic 的 `Critic`，输入同样的特权信息（`src/supermimic/baselines/ppo.py`）；
- SuperMimic 用大世界模型、256 个环境；PPO 用 1024 个环境（CPU 运行），超参数是常用默认值，没有调过；
- 两者各给 8 分钟训练时间（会话环境的 4 核 CPU，单种子），同时按时间和按仿真步数评估。

结果见 `docs/results/vehicle_compare_ppo_cpu.json`，以及同名的 `_curves.png` 和 `_s_curve.png`。

1. **样本效率：SuperMimic 高约 3–4 倍。** 达到约 0.8 的回报，SuperMimic 用了约 50 万步，PPO 用了约 200 万步。这是世界模型方法的预期优势，在车辆上成立。

3. **两者都能泛化到没见过的 S 弯**，在三档摩擦下都跑完了。PPO 的横向误差约为 SuperMimic 的 1/4 到 2/5；SuperMimic 在弧线段跑宽（μ=1.0 时最大约 0.95 m），与 §3.10 的观察一致。
4. **对这个方向的含义**：在“低维动作（2 维）、便宜仿真器、单一跟踪任务”这种设定下，PPO 是强基线，SuperMimic 只在样本效率上占优。论文在人形上的优势来自高维动作和昂贵的接触仿真；车辆要体现世界模型的价值，需要换到样本昂贵的设定：仿真器更贵（高保真多体、实车数据，E7）；或者可微世界模型能带来 PPO 拿不到的东西，比如梯度驱动的裕度分析（E5）、系统辨识和适应（论文 §6）。

**局限**：
- 单种子。§3.10 的经验是单次运行的数字波动很大：SuperMimic 在同样设置的上一次 8 分钟运行里只到 0.55，两次的区别只在评估的次数和时机；
- 只在 CPU 上跑过。H200 上 PPO 可以开到更多环境，墙钟时间的差距可能更大；
- PPO 没有调参，SuperMimic 也只用了 §3.10 验证过的设置，两者都可能还有提升空间；
- 只比较了一种 S 弯（15 m/s、0.7μg）。

### 3.12 NMPC 基线（`src/supermimic/baselines/nmpc.py`）

**设定**：
- 预测模型：单轨模型（8 个状态：位姿、车身速度、横摆角速度、前轮转角、纵向执行器状态），每个轴一条魔术公式侧向力曲线；
- 轮胎参数从完整仿真器辨识：随机正弦转向、6–30 m/s、μ=1，把每个轴的侧向力对单轨侧偏角做最小二乘拟合，相对 RMS 误差前轴 4.9%、后轴 3.2%；摩擦按 PAC2002 的方式缩放（峰值乘 μ，侧偏刚度不变）。没建模的部分：侧倾、俯仰和载荷转移（只在拟合里平均进去）、外倾、联合滑移、车轮转动；
- 执行器：转向伺服、0.4 rad/s 转向速率上限、纵向一阶滞后都精确建模；
- 优化：多重打靶，25 段 × 2 个控制步（1 s 视野），RK4；代价是奖励的五项误差，各乘 w/σ²，加输入变化惩罚；CasADi + IPOPT，平移上一步的解做热启动；
- 实现用 CasADi + IPOPT 而不是原计划的 acados：纯 pip 安装，不用编译。求解时间因此偏保守，换 acados 的 RTI 应能快一个数量级。

**两种信息条件**：
- `nmpc`（特权）：读无噪声的真实状态和真实摩擦；没有延迟补偿。只是上限参考；
- `nmpc_onboard`（公平）：只拿策略拿到的信息。位姿（x, y, yaw）是精确的，因为策略的 goal 就是参考在车体坐标系下的表示；其余全部来自策略看到的 12 维车载测量（车速、横摆角速度、ax、ay、转向角、四个轮速、纵向响应），经过一个估计器（`OnboardEstimator`）：侧向速度由 IMU 积分得到（vy' = ay − r·vx），摩擦由卡尔曼滤波估计，量测是实际侧向加速度与单轨模型在估计的 vy 和 μ 下预测值的差（线性区对 μ 不敏感，接近极限才可观测，先验为 1.0）；指令延迟不告诉它，它按假定的 1 个控制步，用已发出的指令把状态向前预测来补偿。

**评估条件**（所有方法相同，`--eval-noise`、`--eval-delay`、`--eval-mismatch`）：干净（原来的评估）；带训练时的测量噪声加固定 2 步指令延迟；再加上轮胎刚度 ×0.85、质量 ×1.15、质心前移 0.1 m（训练范围的边缘；NMPC 的模型仍是名义值）。策略用的是 §3.11 的同一份训练结果（SuperMimic 2700 次迭代，PPO 408 次更新），没有重新训练。结果见 `docs/results/vehicle_nmpc_fair_cpu.json`。

**S 弯横向误差 [m] 和回报**（μ 0.5 / 0.8 / 1.0；括号内为留出弯道的终止率最大值）：

| 条件 | SuperMimic | PPO | NMPC（特权） | NMPC（车载信息） |
|---|---|---|---|---|
| 干净 | 0.24 / 0.31 / 0.27（回报 0.86 / 0.82 / 0.80） | 0.09 / 0.13 / 0.16（0.98 / 0.96 / 0.92） | 0.03 / 0.02 / 0.02（0.99） | 0.02 / 0.01 / 0.02（0.99） |
| 噪声 + 2 步延迟 | 0.25 / 0.31 / 0.25 | 0.08 / 0.11 / 0.13 | 0.03 / 0.08 / 0.19，μ=1.0 的 S 弯终止（留出弯道最多 33% 终止） | 0.02 / 0.01 / 0.01（0.99，无终止） |
| 再加参数失配 | 0.26 / 0.33 / 0.24 | 0.08 / 0.10 / 0.12 | 0.04 / 0.16 / 0.25，μ=0.8 和 1.0 的 S 弯终止（留出弯道最多 50% 终止） | 0.03 / 0.02 / 0.01（0.99，无终止） |

求解时间（CPU）：NMPC 每步约 8–10 ms（p95 约 14 ms，0 次求解失败）；两个策略每步约 0.05–0.13 ms。

**结论**：
1. **更正我之前的判断。** 我在第一版里说 NMPC 的优势“很大一部分来自特权信息”，这是错的。把特权信息拿掉之后，NMPC 的成绩没有变差，反而在有延迟时更好（特权版没有延迟补偿而失败，车载版有）。在这个任务上，只用策略能用的信息，NMPC 的横向误差仍是厘米级，PPO 的 2–10 倍小，SuperMimic 的 7–35 倍小，而且在噪声、延迟和参数失配下都没有退化；
2. 这不意味着学习方法“没用”，而是说明在这个设定下它没有占到便宜。设定对 NMPC 有利：2 维动作、短视野、平滑的单轨模型就能描述的车、质量和几何参数已知，估计器只需要估 vy 和 μ，执行器模型精确。学习策略还要从数据里自己找出这些；
3. 学习策略的优势只剩部署代价：每步约 0.1 ms，NMPC 约 9 ms（约 90 倍），而且不需要在线求解器、估计器和手工调的权重。NMPC 的“公平”版本还额外依赖：离线辨识轮胎、手写的状态/摩擦估计器、延迟假设；
4. 对论文主线的含义：要在车辆上体现世界模型方法的价值，不能靠“比 NMPC 跟踪得更准”，得换一个 NMPC 做不好的设定：模型失配大到单轨模型不够用（高保真多体、轮胎严重非线性、载荷转移主导）；动作维度高（扭矩矢量、四轮独立驱动）；没有现成的参数化模型（实车数据）；或者需要世界模型的梯度（裕度分析、辨识）。

**局限**：
- 单种子，CPU 评估，策略只有一份训练结果；NMPC 本身是确定性的，但估计器的噪声每次不同，没有做多次噪声种子的统计；
- 公平版 NMPC 的信息仍然多于策略：位姿精确，质量、质心、几何、执行器参数都是名义值而且“碰巧”正确；评估里的失配只在训练范围的边缘；失配更大（例如质量 ×1.5、轮胎换型号）时没有测；
- 特权版的失败有一部分来自它没有延迟补偿，不是信息不够；
- 估计器和 NMPC 权重没有调参，只验证了 S 弯和随机弯道。

### 3.13 麋鹿测试 demo（`scripts/vehicle/elk_test.py`）

**赛道**（`src/supermimic/vehicles/elk.py`）：ISO 3888-2 的避障变道。标准原文要付费，尺寸取自二手资料（2026-11-06 更正，见下）：

| 段 | 长度 [m] | 车道宽度 | 位置 |
|---|---|---|---|
| 1 入口 | 12 | 1.1b + 0.25 | 中心 y = 0 |
| 2 | 13.5 | （过渡，无车道） | |
| 3 避让 | 11 | b + 1 | 向左，与入口车道之间留 1 m 间隙（中心相距约 3.5 m） |
| 4 | 12.5 | （过渡，无车道） | |
| 5 出口 | 12 | 1.3b + 0.25，至少 3 m | 右边界与入口车道对齐（假设） |

b 是车宽（1.8 m），全长 61 m。依据：段长、全长 61 m 和“第 4 段比第 2 段短 1 m”有多个二手来源一致；“第 3 段宽 b + 1 m、第 5 段至少 3 m”来自一个转述 ISO 3888-2:2011 表 1 的页面；“1 m 横向偏移”来自 VEHICO 的描述和 2002 版预览图上的标注。我把 1 m 理解为两条车道之间的间隙，而不是中心距：这样中心相距约 3.5 m，与一篇论文表格里的 “3.5” 一致，也和真实车辆的成绩吻合（通过基准 72 km/h，纪录约 91 km/h）。**没有核对标准原文的部分**：1 m 的含义、出口车道怎样对齐、锥桶间距（取约 3 m）和锥桶底座半径（取 0.15 m）。

**更正**：第一版写的是“中心偏移 1 m、第二车道宽 1.2b + 0.25”。后者其实是 ISO 3888-1（双移线）的宽度；前者让 NMPC 在干路上 130 km/h 都能通过，远超真实车辆的纪录，说明理解错了。第一版的结果作废。

**其余设定**：
- 评分按标准的“没有锥桶被碰倒”：锥桶底座圆与车道边界相切，车身矩形碰到底座圆就算碰桶；另报一个更严的“出线步数”（车身角超出车道线）；
- 标准的流程是用能保持车速的最高档进入、进入后松油门，这里换成匀速参考；
- 参考线：先求在 0.85 μg 侧向加速度预算内能留出的最大间隙，再取间隙为它和 0.10 m 中较小者时曲率峰值最小的线（有余量时平缓，接近极限时用满预算），由特权 NMPC 沿线开出（横向权重收紧），这样参考线可行，而且它自己不碰桶；NMPC 自己都过不去的速度不算作测试点。最小曲率线的峰值曲率 0.023 1/m，对应质点在 1 g 下约 74 km/h；
- 策略是 §3.11 那份（SuperMimic 2700 次迭代、PPO 408 次更新），没见过这个动作，没有重训；NMPC 用车载信息版（§3.12）。

**结果**（CPU，`docs/results/vehicle_elk_cpu.json`、`vehicle_elk_paths.png`、视频 `vehicle_elk.mp4`）。参考线能生成到干路 60 km/h、湿滑路（μ=0.5）45 km/h；更快时 NMPC 在线上自己就会碰桶，或者在 0.85 μg 内找不到线。每格是“碰到的锥桶数 / 出线步数 / 最大横向误差 [m]”：

| 路面和入场速度 | SuperMimic | PPO | NMPC（车载信息） |
|---|---|---|---|
| μ=1.0，40 km/h | 2 / 27 / 0.44 | 2 / 0 / 0.10 | **0** / 0 / 0.02 |
| 45 | 2 / 31 / 0.52 | 2 / 4 / 0.17 | **0** / 0 / 0.02 |
| 50 | 3 / 37 / 0.62 | 3 / 9 / 0.25 | **0** / 0 / 0.02 |
| 55 | 5 / 42 / 0.74 | 3 / 13 / 0.33 | **0** / 0 / 0.03 |
| 60 | 5 / 53 / 0.87 | 3 / 17 / 0.40 | **0** / 0 / 0.05 |
| μ=0.5，30 km/h | 3 / 59 / 0.35 | 1 / 0 / 0.10 | **0** / 0 / 0.01 |
| 35 | 2 / 28 / 0.39 | 1 / 0 / 0.08 | **0** / 0 / 0.02 |

最高通过入场速度：NMPC 干路 60、湿滑路 45 km/h（都是参考线能生成的上限）；两个策略在所有速度都碰桶。

带测量噪声、2 步延迟和参数失配（刚度 ×0.85、质量 ×1.15、质心前移 0.1 m）重测：NMPC 干路最高 55（60 时碰 6 个桶）、湿滑路 40（45 时碰 3 个）；PPO 干路 40、湿滑路 30–40 都通过了；SuperMimic 仍全部碰桶。PPO 在这种条件下反而在低速通过，是因为它的接触都是擦边（误差约 0.1 m，正好等于参考线的间隙），一点扰动就能让结果翻转。这说明在这套几何下，单次通过与否对小扰动很敏感，需要多次重复才能下结论。

**结论**：
1. 真实尺寸下，麋鹿测试是一个厘米级的精度测试：入口车道两侧各只有约 0.2 m 余量，参考线离锥桶只有 0.10 m。车载信息版 NMPC 的横向误差 1–6 cm，能过；PPO 0.1–0.4 m，擦到 1–3 个桶；SuperMimic 0.35–0.9 m，碰 2–5 个桶，还大段出线；
2. 两个策略都是用 σ_lat = 0.5 m 的奖励训练的，对 10 cm 级的误差几乎没有惩罚，所以这个结果主要说明它们的训练目标不要求这种精度，不是说它们学不会；
3. 参考线由 NMPC 生成，NMPC 跟踪它有天然优势，这一点仍然成立；
4. 我们的极限速度（干路 60 km/h）低于真实车辆（72–91 km/h）：参考线只用到 0.85 μg、匀速而非松油门、轮胎和车型不同，而且锥桶接触判定严格。

**局限**：赛道细节未经标准原文核对（见上）；每个速度一条参考线、一次运行；策略只有一份训练结果，SuperMimic 只训练了 2700 次迭代；全在 CPU 上。

## 4. 参考与 ξ 的耦合：一个需要专门处理的问题

人形里参考动作和 ξ 基本独立：摩擦变化不会让一个走路动作变得不可行。车辆不同：一条按 μ=1.0 规划的赛车线，在 μ=0.6 时物理上就跟不住。

可选方案，按推荐顺序：

1. **参考随 ξ 生成**（默认）：路径几何固定，速度曲线按当前回合的 μ 用 g-g 图重新规划。简单，但部署时需要 μ 的估计才能生成参考。
2. **速度比例接口**：参考只给路径几何加“允许使用的附着比例” κ∈(0, 1]，速度由策略自己决定，奖励改为“沿路径前进速度 × 跟踪精度”。策略要隐式估计 μ，更接近真实赛车，但奖励不再是纯跟踪。
3. **不可行就截断**：保留原参考，跟踪误差超过阈值就终止。实现最简单，但会浪费大量回合在不可行的片段上（类比人形数据里那 452 条杂技片段）。

先用方案 1 跑通，再把方案 2 作为第二个接口（对应论文 Appendix B 的多接口训练，也对应 D7b 方向）。

## 8. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 饱和区雅可比不准（C4） | E1 余弦相似度低；策略不敢逼近极限，或者逼近后失控 | 按饱和程度给世界模型损失加权；在饱和区加采样（D1）；集成模型，用方差惩罚；必要时混合：学来的模型做前向，简化可微模型求梯度（DMO / Song et al. 的思路） |
| 超过极限后混沌（打滑甩尾） | 梯度爆炸，训练发散 | 软存活权重本来就会截断失控后的贡献；梯度裁剪（论文的两级裁剪）；必要时用自适应视野 |
| 不可微逻辑（ABS/ESC、换挡） | 世界模型在门限附近误差高 | 先关掉，确认基础版可行后再打开，作为“黑盒兼容性”的专门实验 |

## 10. 下一个方向：集成底盘控制（2026-11-07）

### 10.1 为什么换方向

§3.11–§3.13 的结果有一个清楚的规律：在“2 维动作（前轮转角、纵向加速度）、单轨模型就够、参数已知”的设定下，只用车载信息的 NMPC 也稳赢两个学习方法（§3.12），学习方法只在推理速度上占优（约 0.1 ms 对 9 ms）。论文在人形上的优势来自高维动作和强耦合的接触力，这个设定里两样都没有。

集成底盘控制（intelligent chassis control）把这些条件补上：
- **动作维度高、彼此冗余**：前轮转角、后轮转角、各轮驱动和制动扭矩、悬架（主动防倾杆、半主动减振器或主动作动器），合计可达 10–12 维；同一个横摆力矩可以由转向、扭矩矢量、载荷转移多种方式实现；
- **耦合强**：所有执行器最终都作用在同一组轮胎力上；悬架通过垂向载荷改变轮胎能给出的力，调前后防倾刚度的分配就能改变不足转向特性，所以悬架直接影响极限操控；
- **对 NMPC 不利**：单轨模型不再够用，全耦合模型的状态 27+、输入 10+，还要覆盖车轮跳动（10–15 Hz）。工业界因此分层设计（各子系统各自控制，再加协调层），在强耦合工况下不是最优；
- **对学习方法有利**：一个策略直接输出所有执行器，不需要手工设计分配；PPO 的随机探索随维度变差，SuperMimic 的世界模型梯度原则上不受维度影响；推理代价不随执行器数量明显增长。

### 10.2 维度与复杂度

| | 现在 | 阶段 1：操控类执行器 | 阶段 2：完整悬架 |
|---|---|---|---|
| 动作 | 2 | 5：前轮转角、纵向加速度、后轮转角、横摆力矩（后轴左右扭矩差）、前后防倾刚度分配 | 10–12：再加四个减振器或作动器，四轮扭矩独立 |
| 仿真器 | 双轨 + PAC2002，侧倾和俯仰为二阶近似，平路 | 同上；后轮侧偏角和力的分解加入后轮转角，载荷转移按可调的防倾分配 | 加车身垂向、四个簧下质量、可调减振、路面激励（ISO 8608）、车轮离地 |
| 目标 | 跟踪 | 跟踪（执行器冗余由动作变化率惩罚约束） | 跟踪、乘坐舒适、抓地（轮胎载荷波动）互相冲突，报告帕累托前沿 |
| 时间尺度 | 50 Hz 控制 | 同上 | 悬架需要 100 Hz 以上，想象视野的 BPTT 步数随之增加 |
| 外部验证 | CommonRoad 多体模型（E0） | 新增部分无外部参照，只能做物理一致性测试 | CommonRoad 多体模型有车身垂向和簧下质量（按轴），被动悬架可以对拍；主动部分和路面没有参照 |

复杂度主要涨在仿真器保真度、世界模型精度（纵向滑移和垂向振动都很“硬”）、奖励权重和公平基线上，学习框架本身改动不大。阶段 1 的工作量约为现有车辆部分的 1.5–2 倍；阶段 2 约 5 倍以上。

### 10.3 分阶段计划和关卡

| 阶段 | 内容 | 关卡 |
|---|---|---|
| C1 | 5 维操控类执行器（本节实现，`VehicleEnvCfg(chassis=True)`）；在同一个随机弯道库上训练 SuperMimic 和 PPO，与 2 维版本对比 S 弯、留出弯道和麋鹿测试 | 维度从 2 到 5，SuperMimic 相对 PPO 的样本效率优势是否变大；额外执行器能否提高麋鹿测试的通过速度或减少碰桶 |
| C2 | 纵向滑移的雅可比检查（E1 的扩展）；四轮扭矩独立（7 维）；基线：上层 MPC + 二次规划分配 | 世界模型在纵向滑移饱和区的梯度可信；学习方法在执行器故障（一个电机失效）下明显好于固定分配 |
| C3 | 完整垂向动力学、路面激励和预瞄（预瞄作为 goal 输入，接口不变）、舒适目标、100 Hz 以上的控制 | 被动悬架与 CommonRoad 多体模型对拍误差 < 5%；在不平路面的麋鹿测试上，学习方法的帕累托前沿不劣于“天棚控制 + 分层协调”基线 |

如果 C1 的第一个关卡不成立（维度变大，样本效率优势并没有变大），集成底盘控制也救不了这个方向，应转向实车数据或系统辨识（§7）。即使到高维，有一个好分配器的 MPC 在跟踪精度上很可能仍然领先；论文的论点应放在计算预算、故障下的适应和免手工分配上，而不是“跟踪得更准”。

### 10.4 C1 的实现（`chassis=True`）

- **动作**（5 维，原始值经 tanh 压缩）：前轮转角指令（±0.2 rad，同前）、纵向加速度（±6 m/s²，同前）、后轮转角（±0.07 rad，一阶伺服 0.05 s，速率上限与前轮相同）、横摆力矩（±3000 N·m，一阶响应 0.05 s，由后轴左右驱动扭矩差 ΔT = M·R_w / T_r 实现）、前后防倾刚度分配的偏移（名义前轴份额 ±0.2，一阶响应 0.1 s，总侧倾刚度不变）；
- **仿真器**：后轮侧偏角减去后轮转角，后轮力按后轮转角旋转到车身系；载荷转移按当前的前后分配；默认 `chassis=False` 时与原来逐位相同；
- **执行器状态**进入记录的状态（后轮转角、横摆力矩、分配偏移），世界模型里它们和原有执行器一样精确更新；观测加入这三个执行器状态和 5 维上一动作；
- **基线**：PPO 直接用 5 维动作；NMPC 仍是 2 维（底盘执行器保持中性），作为“没有集成底盘控制的传统控制器”参照。C2 再加真正的分配基线。

### 10.5 C1 的第一次结果（`scripts/vehicle/chassis_demo.py`）

**第一次 5 维训练，SuperMimic 崩了**（`docs/results/vehicle_chassis_run1_no_usage_cost.json`）：留出弯道回报 0.07–0.12，比没训练时（0.09）还差，三条 S 弯全部终止；PPO 正常（0.93–0.95）。诊断：

- 策略把底盘执行器推到边缘并且有偏：平均横摆力矩约 −1000 N·m，后轮同相转角接近饱和，防倾分配接近极限。PPO 对它们用得很少。

**C1 关卡的判断**：
1. **“维度变大，SuperMimic 的样本效率优势变大”在这个预算、单种子下不成立，而且方向相反**：PPO 在 5 维下学得一样快（达到 0.7 都是 203 万步），终局还更准（μ=1.0 的 S 弯横向误差从 0.16 降到 0.09 m，说明额外的执行器确实有用）；SuperMimic 在同样 69 万步下从 0.80 掉到 0.43；
2. 原因不是方法上限，而是**世界模型对新执行器的建模**：它要学会后轮转角、横摆力矩和防倾分配的效果，在数据还少的时候策略就开始利用它的错误；即使加了使用代价，SuperMimic 仍把防倾分配推到接近饱和（平均 |指令| 0.84），而这正是本仿真器在接近极限时内侧前轮几乎离地、响应不规则的区域（`tests/test_chassis.py` 中有记录）；
3. 这是论文方法在高维动作下应该面对的问题。人形里同样有“策略利用世界模型误差”的风险，论文靠大规模数据和集成来抑制。对车辆，下一步要试的是：世界模型集成，用不确定性惩罚策略（§8 的缓解之一）；更大的探索噪声或针对底盘维度的随机激励，让世界模型先见过这些执行器；更长的训练（在 H200 上）；把防倾分配的作用范围收窄，或修正离地附近的仿真。在做这些之前，不能说集成底盘对 SuperMimic 是更好的方向，也不能说更差，只能说**第一次尝试暴露了世界模型这一关**。

**局限**：单种子、CPU、一组超参数（沿用 2 维的）；使用代价只试了一个权重；5 维和 2 维的回报定义因使用代价而略有不同。

结果写进 runbook 第 9 步。

### 10.6 世界模型集成、不确定性惩罚和底盘探索激励

**做法**（框架层面，与机器人无关；默认关闭时训练逐位不变）：
- **世界模型集成**（`WorldModelCfg.ensemble`）：3 个独立初始化的动力学网络，每个在同样的窗口上各自做自回归展开来训练；想象时用它们的平均增量；
- **不确定性惩罚**（`PolicyTrainerCfg.uncertainty_penalty`）：成员预测增量（归一化后）的方差，按分量取平均作为“分歧”，从想象奖励里扣掉 λ × 单步最大奖励 × 分歧（λ = 10）。分歧对动作可微，所以梯度会把策略推离模型不确定的区域；实际分歧约 0.003–0.006，扣掉单步最大奖励的 3–6%；
- **底盘探索激励**（`compare_ppo.py --chassis-explore`）：SuperMimic 采数据时，在三个底盘动作上叠加缓慢变化的随机噪声（Ornstein–Uhlenbeck 过程，标准差 0.5，相关时间 0.3 s），让世界模型早点见到这些执行器的效果。

**消融**（5 维动作，各 2700 次迭代 = 69 万仿真步，种子 0，CPU，都带使用代价；`docs/results/vehicle_chassis_ablation.json`）：

- 收窄防倾分配的范围，或修正车轮接近离地时的仿真，再复测；
- 多种子，在 H200 上加长训练。

**局限**：每组单种子；λ、探索噪声强度只各试了一个值；5 维的回报包含使用代价，与 2 维不严格可比（横向误差和碰桶数可比）。

### 10.7 用 NMPC 采集的数据给世界模型热启动

**动机**：§10.6 剩下的差距（横向精度差、防倾分配被利用）看起来像数据覆盖问题：SuperMimic 早期的策略开得很差，世界模型只能从这些数据里学底盘执行器的效果。NMPC 一直开得很好，可以拿它先采一批“好开法 + 底盘激励”的数据。

**做法**（`compare_ppo.py --nmpc-data-steps 3000 --nmpc-data-envs 32`；缓存 `--nmpc-data-cache`）：
- 特权信息 NMPC 在训练弯道库上开车，32 个环境 × 3000 步，共 97293 条（CPU 上采了 1909 s，不计入 SuperMimic 的训练时间和仿真步数）；
- NMPC 只管前轮转角和加速度，这两维加标准差 0.15 的白噪声；三个底盘动作 NMPC 不用，加标准差 0.5 的 OU 激励（与 §10.6 的探索激励相同）；
- 世界模型先在这批数据上训练 200 次，然后进入正常的 SuperMimic 循环；
- 两种用法：(a) 之后每个世界模型批次和想象起点批次都有 30% 来自这批数据（`MixedReplay`，`--nmpc-data-frac 0.3`）；(b) 只用来预训练（`--nmpc-data-frac 0`，现在是默认值）。

1. **数据覆盖确实是 §10.6 剩下问题的主因之一**：只多了一次性的 NMPC 预训练，5 维 SuperMimic 的留出回报 0.71 → 0.77（这一项的差别后来证实在单种子噪声以内，见 §10.8 第 4 点），S 弯横向误差回到 2 维的水平（0.22–0.30 m 对 0.24–0.31 m），麋鹿测试碰桶数从 6–13 个降到每档 3 个，和 2 维相当；防倾分配的使用从 0.80 降到 0.48（PPO 0.20），没被推到饱和；
2. **但不能一直混入**：(a) 中途达到过 0.64（1960–2060 次迭代），最后掉到 0.35，留出弯道大量终止。混入后防倾分配几乎不用了（0.10），但后轮转向被推到 0.30（PPO 0.12），S 弯 μ=1.0 上（第 313 步终止前）横摆力矩平均偏置约 −570 N·m：被利用的维度换了一个，而不是消失。我的推测（未单独验证）：NMPC 数据集中在贴着参考线的状态，占了固定 30% 的批次后，世界模型在策略自己会走到的偏离状态上数据变少；同时 30% 的想象起点来自 NMPC 的状态，策略在这部分起点上学到的东西用不到自己的分布上。可以分别关掉窗口混入和起点混入来区分；
3. **样本效率没有变好**：按评估点算，(b) 第一次达到 0.7 是在 69 万步（51 万步时 0.697），§10.6 是 57 万步；再加上 9.7 万条 NMPC 数据，总数据量更多。所以 NMPC 预训练改善的是最终质量和精度，不是关卡要的“维度变大、样本效率优势变大”。C1 的第一个关卡仍未通过；
4. **和 PPO 的差距仍然大**：PPO 5 维回报 0.96、横向误差 0.07–0.10 m。SuperMimic 现在在 5 维上“不比 2 维差”，但离 PPO 的精度还远，原因与 2 维相同（§3.11：预算内的训练量不够，横向误差主导），不是底盘维度特有的问题。

**局限**：单种子；NMPC 数据量、噪声、预训练次数、混入比例都只试了一组；(a) 和 (b) 都比 §10.6 多了 NMPC 采数的 32 分钟 CPU 时间；NMPC 用了特权信息（在仿真里采示范是合理的，但真车上要换成车载版本）。

**下一步**：
- 多种子复查 (b) 和 §10.6 的差距（0.06 在单种子噪声的量级以内，碰桶数和横向误差的改善更明显）；
- 区分 (a) 失败的原因：只混世界模型窗口、只混想象起点，或随训练逐步降低混入比例；
- 防倾分配：收窄范围或修正车轮接近离地时的仿真后复测；
- 进入 C2（加主动悬架）之前，先在 H200 上加长训练，看 SuperMimic 5 维能否接近 PPO 的精度。

### 10.8 世界模型是太小，还是训练不够长？

§10.7 之后的问题：5 维 SuperMimic 离 PPO 的精度还远，限制它的是世界模型不够大，还是训练不够长？做了两个实验（种子 0，CPU；`docs/results/vehicle_chassis_wm_capacity.json`）。

**实验 1：训练加长一倍**。§10.7 (b) 的设定（集成 3、惩罚 10、探索 0.5、NMPC 数据只预训练），从 2700 次迭代加到 5400 次（69 万 → 138 万仿真步）：

| 迭代 | 1140 | 1960 | 2700 | 3040 | 3920 | 4020 | 4700 | 4980 | 5400 |
|---|---|---|---|---|---|---|---|---|---|
| 留出弯道回报 | 0.37 | 0.56 | 0.68 | 0.69 | **0.45** | 0.78 | **0.50** | 0.62 | 0.61 |
| S 弯回报 | 0.69 | 0.70 | 0.75 | 0.86 | 0.64 | 0.84 | **0.35** | **0.35** | 0.66 |
| 世界模型 8 步误差 | 0.47 | 0.31 | 0.22 | 0.18 | 0.18 | 0.21 | 0.14 | 0.18 | **0.12** |
| 集成分歧 | 0.0034 | 0.0046 | 0.0043 | 0.0043 | **0.0071** | 0.0049 | **0.0083** | 0.0064 | 0.0054 |

最后一次的留出回报 0.61，S 弯 μ=1.0 终止，横向误差 0.43–0.59 m，都不比 2700 次时好。世界模型的误差一直在降（0.22 → 0.12），策略却在 0.45–0.78 之间来回摆。两次大跌（3920、4700 次迭代）都伴随集成分歧升高到平时的 1.5–2 倍，说明策略走进了世界模型不确定的区域。

**实验 2：离线比较世界模型大小**（新脚本 `scripts/vehicle/wm_capacity.py`）。取实验 1 第 2700 次迭代时的回放数据（`compare_ppo.py --save-buffer-at 2700`），256 个环境里留出 32 个做测试，其余 6.7 万条用来从头训练不同大小的单个动力学网络，训练设置与在线训练相同：

| 隐藏层 | 参数量 | 留出 8 步误差：1000 / 3000 / 6000 次更新 | 训练数据上的误差，6000 次 |
|---|---|---|---|
| 256×256（小） | 8.9 万 | 0.73 / 0.38 / 0.20 | 0.17 |
| 512×512（现在用的） | 31 万 | 0.59 / 0.25 / 0.13 | 0.09 |
| 1024×1024 | 114 万 | 0.42 / 0.15 / **0.074** | 0.038 |
| 512×512×512（三层） | 57 万 | 0.49 / 0.18 / **0.072** | 0.050 |

在线训练到第 2700 次迭代时，世界模型大约做了 2600 次更新。

**怎么读**：
1. **单看世界模型，两个原因都成立**：同样的数据和更新次数，更大的模型误差明显更低（3000 次更新时 1024 宽 0.15，对现在的 0.25）；三层 512 用一半参数达到与 1024 宽相同的误差，加深比加宽划算。所有模型到 6000 次更新时还在降，所以更新次数也不够；
2. **但世界模型的误差不是策略的瓶颈**：实验 1 里在线世界模型误差从 0.22 降到 0.12（相当于离线实验里从 512 到 1024 的差距），策略没有变好，反而更不稳定。所以单纯把世界模型做大或训得更久，未必能换来更好的策略；需要直接在线试大模型才能下结论（见下一步）；
3. **训练数据开始不够**：大模型在训练数据上的误差只有留出数据上的一半（1024 宽：0.038 对 0.074），开始过拟合。原因是回放缓冲区很小：每个环境只保留最近 300 步（`replay_capacity = episode_steps + 50`），整个缓冲区 7.7 万条，约 6 秒驾驶 × 256 个环境。策略一变，旧状态区域的数据很快被覆盖，世界模型会“忘掉”策略刚离开的区域；策略回去时就会利用这些误差。这是实验 1 中策略来回摆的一个合理解释（未验证）；
4. **单种子的噪声比之前估计的大**：实验 1 的前 2700 次迭代与 §10.7 (b) 设定完全相同，只是评估点不同（评估会改变随机数序列），2700 次时的留出回报是 0.68，§10.7 (b) 是 0.77。所以 §10.6 和 §10.7 之间 0.71 → 0.77 的差别在单种子噪声以内，不能当作 NMPC 预训练的效果；横向误差和碰桶数的改善更大，但同样需要多种子确认。

**结论**：既不是单纯“太小”，也不是单纯“不够长”。世界模型做大、训久都能降低它的误差，但现在限制策略的是训练不稳定：策略在世界模型不确定的区域来回进出。数据（缓冲区太小）是最可疑的原因。

**下一步**（按代价从小到大）：
- 加大回放缓冲区（例如每个环境 2000 步），看策略的摆动是否减小。只需改 `replay_capacity`；
- 在线用三层 512 的世界模型训练（参数是现在的 1.85 倍），直接检验更准的世界模型能否换来更好的策略；
- 不确定性惩罚随分歧自适应，或在分歧升高时减小策略步长；
- 以上都至少用 3 个种子。

## 11. 复盘与方向调整（2026-11-08）

### 11.1 做过什么，说明了什么

| 实验 | 结果 | 对 SuperMimic 的含义 |
|---|---|---|
| 仿真器（§3.1） | 与 CommonRoad 多体模型误差 < 5%；H200 上 1.3×10⁷ 步/s，4 核 CPU 上约 10⁵ 步/s | 数据几乎不要钱 |
| 饱和区梯度检查（§3.9） | 大世界模型在极限处的 8 步动作梯度余弦 0.94 | 极限附近的梯度可用 ✓ |
| 对比 PPO，2 维（§3.11） | 达到同样回报 SuperMimic 少用 3–4 倍样本；同样训练时间 PPO 更好（0.96 对 0.81，横向误差小 2–4 倍） | 优势只在样本数上 |
| 车载信息 NMPC（§3.12、§3.13） | 横向误差厘米级，噪声、延迟、失配下不退化，麋鹿测试全部通过 | 学习方法在精度上没有位置，只在推理代价上占优（约 0.1 ms 对 9 ms；换 acados 后差距估计缩小约一个数量级） |
| 5 维底盘（§10.5–§10.7） | PPO 不变慢；SuperMimic 先崩，修到与 2 维持平 | “维度越高越有利于 SuperMimic”没有出现 |
| 世界模型大小与训练长度（§10.8） | 做大、训久都能降低世界模型误差，策略却不跟着变好，来回摆动；单种子噪声约 0.09 | 瓶颈是训练稳定性 |

**总结**：车辆轨迹跟踪有很好的物理模型，所以 NMPC 赢；仿真又极便宜，所以 PPO 赢。SuperMimic 的两个卖点，省样本和从黑盒仿真器学一个可微代理，在这个问题里都不值钱。这不是算力问题：
1. 样本几乎不花时间。PPO 的 1337 万步，在 H200 上光仿真约 1 秒，GPU 越强 PPO 越占便宜；
2. 就算 SuperMimic 追上 PPO 的 0.96，横向误差仍是 NMPC 的数倍；
3. 策略来回摆动是训练不稳，规模放大不会自动解决；
4. GPU 的合理用途是多种子确认已有结论，不是出成果的路径。

**保留的价值**：经过对拍的仿真器、极限处梯度可靠性的检查方法、两个公平的 NMPC 基线、麋鹿测试、集成和不确定性惩罚、示范数据预训练，以及一组诚实的负面结果（“学到的世界模型在车辆控制里什么时候有用、什么时候没用”）。

### 11.2 SuperMimic 需要什么样的问题

四条同时满足：
- **样本贵**：仿真器慢，或者用实车数据；
- **没有好用的第一性原理模型**：NMPC 失去模型优势；
- **很多工况共用一套动力学**：一个世界模型覆盖全部工况，摊销训练成本；
- **部署要求推理便宜**。

### 11.3 推荐方向：越野、可变形地面上的高速驾驶

数据来自慢的、不可微的高保真仿真器：Project Chrono 的车辆模块加可变形地面（SCM）。

| 条件 | 怎么满足 | 依据 |
|---|---|---|
| 样本贵 | 多体加地面变形，按文献约为实时（见 §11.4），比我们的仿真器慢几个数量级。PPO 的千万步变成真实成本 | Chrono 开发者论坛；月面传感器仿真论文报告基础场景实时因子 ≤ 1，带可动石块时 30–40；AC2MPC 在 Chrono 的沙地和黏土上做实验 |
| 没有好用的物理模型 | 地面力学（Bekker–Wong）的参数未知，随地面变化；单轨加魔术公式描述不了沉陷和推土阻力 | 文献普遍转向学习模型：Koopman 预测器加 MPC（arXiv 2603.28965）；function encoder 加递推最小二乘再接 MPPI（arXiv 2509.12516）；元学习在线适应（arXiv 2504.16923） |
| 共用一套动力学 | ξ 换成地面参数（承压模量、内聚力、内摩擦角等），一个世界模型覆盖所有地面 | AnyCar（arXiv 2409.15783）用 1 亿步、四个仿真器训练通用动力学模型，实车上比专用模型最多好 54% |
| 推理便宜 | 策略每步约 0.1 ms | AnyCar 用的 MPPI 每步 600 条采样，在 RTX 4090 上 20 ms |

（文献数字只来自摘要和第三方总结，没有读全文核实。）

**研究问题**：
1. **摊销策略对在线 MPPI**：在同一个学到的世界模型上，SuperMimic 训练出的策略和 MPPI 相比，精度差多少，推理代价差多少（预计相差百倍以上，决定能否上嵌入式）？
2. **样本有成本时对 PPO**：同样的墙钟时间和仿真器调用次数下，谁先到目标回报？
3. **NMPC 的模型失配**：单轨 NMPC（辨识过的轮胎）在可变形地面上退化多少？
4. **跨地面泛化**：没见过的地面参数下，策略能否只凭观测历史保持稳定（对应 RQ4）？

**可复用**：世界模型、BPTT、critic；集成和不确定性惩罚；示范数据预训练（NMPC 示范换成 MPPI 示范）；评估框架；梯度可靠性检查方法。

**风险**：
- 接 Chrono 的工程量大。PyChrono 通过 conda 发布，以 CPU 为主，需要多进程并行采数据；
- 学到的模型加 MPPI 可能比摊销策略更准，那时 SuperMimic 的卖点只剩推理代价和样本代价，要事先接受；
- §10.8 的训练不稳要先解决（从加大回放缓冲区开始）。

### 11.4 关卡

| 关卡 | 内容 | 通过条件 |
|---|---|---|
| G0 样本贵 | 在同一台 4 核 CPU 上，测 Chrono 车辆（刚性轮胎，SCM 地面）在 50 Hz 控制下的环境步/s，含多进程并行 | 比我们的仿真器（4 核 CPU 约 10⁵ 步/s）慢 100 倍以上 |
| G1 物理模型失配 | 单轨 NMPC（轮胎从 Chrono 数据辨识）在 SCM 地面上跟踪随机弯道 | 横向误差是硬地面上的 3 倍以上，或出现终止 |
| G2 样本效率换成时间 | SuperMimic 对 PPO，在 Chrono 上按墙钟时间比较 | SuperMimic 先到目标回报 |
| G3 摊销的代价 | 同一个世界模型上，SuperMimic 策略对 MPPI | 报告精度差距和推理代价，无关卡 |

G0 不过，“样本贵”就不成立，这个方向要重新考虑；G1 不过，NMPC 仍是强基线，卖点只剩推理代价。

**G0 的先验估计**：文献说四轮车在 SCM 上大约实时。50 Hz 控制意味着每个进程每秒约 50 个环境步，4 核约 200 步/s。这比我们的仿真器在同一 CPU 上慢约 500 倍，比 H200 慢约 6×10⁴ 倍。按这个速度，PPO 的 1337 万步要约 18 小时，SuperMimic 的 69 万步约 1 小时。实测之前只是估计。

**G0 的实测（2026-11-08，`scripts/vehicle/chrono_throughput.py`，`docs/results/vehicle_chrono_throughput.json`）**：同一台 4 核 CPU，PyChrono 10.0.0（conda `projectchrono` 渠道；PyPI 上的 `pychrono` 是无关的同名小包，conda-forge 的版本没有车辆模块）。车是 Chrono 自带的 HMMWV 完整模型（双横臂悬架、轴系动力总成、四驱），积分步长 2 ms，按 50 Hz 控制步计数，只计 `Advance` 的时间；每个进程一辆车、Chrono 单线程。驾驶是脚本：油门渐增到 0.8，1 s 后正弦转向。

| 配置 | 1 个进程：控制步/s（墙钟/仿真时间） | 4 个进程合计：控制步/s | 本仿真器（4 核，4096 个环境，8.7×10⁴ 步/s）快多少倍 | 平均车速 |
|---|---|---|---|---|
| 硬地面，TMeasy 操纵轮胎 | 189（0.26） | 562 | **155 倍** | 8.9 m/s |
| SCM 可变形地面，网格 0.10 m，刚性轮胎 | 118（0.42） | 379 | **231 倍** | 4.2 m/s |
| SCM 可变形地面，网格 0.05 m，刚性轮胎 | 55（0.92） | 177 | **494 倍** | 4.2 m/s |

**G0 通过**：三种配置都比本仿真器慢 100 倍以上；与 H200 上的 1.3×10⁷ 步/s 比，SCM 0.10 m 慢约 3.4×10⁴ 倍。并行接近线性（4 个进程时每进程只降 10–15%）。与文献的“约实时”一致（0.05 m 网格时墙钟/仿真时间约 1）。

**怎么读**：
1. **贵的主要是多体模型本身，不是可变形地面**：硬地面的 Chrono 已经慢 155 倍，SCM 只再慢 1.5–3 倍。所以“样本贵”对任何 Chrono 车辆都成立；选可变形地面的理由在 G1（没有好用的物理模型），不在 G0；
2. **换算成训练时间**（SCM 0.10 m，4 核）：PPO 在 §3.11 用了 1337 万步，约 9.8 小时；达到回报 0.8 的 200 万步约 1.5 小时。SuperMimic 达到 0.8 的约 50 万步约 22 分钟，再加上学习本身的计算。同样的硬件上，SuperMimic 的墙钟优势**最多就是样本效率的倍数**（§3.11 测得 3–4 倍），不是数量级的差别；
3. **硬件越多，这个优势越小**：64 核机器上 SCM 约 6000 步/s，PPO 的 200 万步只要约 6 分钟。所以 G2（按墙钟时间比较）必须在固定硬件下做，并同时报告仿真器调用次数；
4. **还没测高速**：这组土壤参数（Chrono 演示用的软土）上车速只有约 4 m/s。SCM 的代价随车速增加（单位时间扫过的网格更多），高速需要更硬的土壤参数，届时要复测。

**下一步**：G1，单轨 NMPC 在 SCM 地面上的模型失配。需要把 Chrono 包成与本仓库相同接口的环境（多进程、50 Hz、参考路径跟踪），并从 Chrono 数据辨识轴轮胎。

### 11.5 备选：拿世界模型做压力测试

用世界模型的梯度，给任意底盘控制器（NMPC、ESC、学到的策略）找最坏的扰动（μ 突变、对开路面、侧风），和黑盒搜索比较找到失效所需的仿真调用次数。好处是代码现成，极限处的多步梯度已验证可靠（§3.9），而且不需要在跟踪精度上赢 NMPC。缺点是离开了策略学习主线；已有工作用可微时序逻辑做梯度引导的场景生成（CONGRAD，ICSE 2026 JAWs），差异要落在“用学到的可微代理替代黑盒仿真器”上。

### 11.6 不再推进

- 把现有实验直接放大到 GPU（只做多种子确认）；
- C2 完整悬架：5 维的结果不支持“维度越高越有利”的前提。
